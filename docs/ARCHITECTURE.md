# Архитектура

Модуль `friendship` выдаёт постоянный уникальный код и хранит одну строку на пару пользователей в `friendship_request`. Пара блокируется через упорядоченные row locks пользователей, сериализующие встречные заявки и переходы состояния. Встречные ожидающие заявки автоматически становятся дружбой. Мобильный клиент использует общий authenticated Dio instance.

Backend — Spring Boot модульный монолит за REST API, PostgreSQL/PostGIS с миграциями Flyway. Мобильный клиент в `mobile/` построен на Flutter/Dart, Riverpod и go_router; scope включает auth, профиль, друзей и первую карту. API клиент использует Dio и отправляет access JWT как Bearer token, а secure storage хранит токены. Карта отображается через MapLibre; источник стиля/тайлов и данные мест отделены интерфейсами, координаты устройства не отправляются в backend. Текущая база запускается отдельно через Docker Compose.

Логические границы: identity (учётные данные/сессии), profiles, friendships, location (согласие и TTL координат), places (поиск мест), meetings (события/участники), routing (маршруты), notifications (outbox/доставка), avatars, houses, safety (блокировки/жалобы). Мобильная карта находится в `mobile/lib/src/map/`: виджет зависит от MapLibre и отдельного поставщика стиля; `MapPlacesSource` задаёт порт будущего получения реальных мест, пока реализаций/фиктивных данных нет. Межмодульные обращения — через публичные интерфейсы приложения, без доступа к внутренним репозиториям.

Поток встречи: REST → аутентификация/валидация → сервис meetings с проверкой полномочий → транзакция PostgreSQL → запись уведомлений/outbox → адаптер доставки. Источник поиска и маршрутов выбирается конфигурацией; провайдеры не протекают в доменные модели. Сейчас внешние адаптеры не реализованы. Маршруты для MVP могут открываться во внешнем приложении, пока нет лицензированного API.

Пространственные данные — PostGIS geography WGS84, spatial index; приватность проверяется до выдачи координат. Расширение нагрузки — реплики stateless backend и индексы/архивация по измерениям. Не добавлять брокер/Redis до появления измеренной потребности. OpenAPI и auth ещё не подключены; API v1 предполагается с момента первой реализации.
