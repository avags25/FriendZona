# Модель данных

Начальная миграция создаёт `app_user`, `meeting`, `meeting_participant`; это минимальный каркас, не полная доменная модель.

- `app_user`: UUID, уникальный email, display name, timestamps и soft-delete отметка; V2 добавляет password hash. Публичный профиль этапа 2 использует только `id`, `email`, `display_name`, `created_at` из этой строки; отдельная таблица профиля не нужна.
- `meeting`: организатор, заголовок/описание, снимок названия/адреса места, provider + provider place id, координаты `GEOGRAPHY(POINT,4326)`, `starts_at TIMESTAMPTZ`, IANA zone, состояние; GiST для геопоиска и индекс времени.
- `meeting_participant`: составной ключ встречи/пользователя, статус, время ответа.
- `V2__authentication_sessions.sql`: добавляет nullable `password_hash` для совместимости с уже существующими строками; создаёт уникальный индекс `app_user_email_normalized_uidx` по `lower(btrim(email))` и `refresh_session` с SHA-256-хэшами непрозрачных refresh-токенов, сроком действия, отзывом и ссылкой на токен-замену. Новые email сохраняются в канонической форме `strip + lowercase(Locale.ROOT)`. Старые строки остаются без изменений; если среди них уже есть email, совпадающие после trim/lowercase, индекс остановит миграцию без потери данных — сначала разрешите дубликаты вручную. Старые аккаунты без `password_hash` не могут войти до контролируемого восстановления пароля.
- V3 добавляет уникальный `app_user.friend_code` и `friendship_request` с внешними ключами, ограничениями статусов и уникальным каноническим ключом пары. Частичные индексы обслуживают входящие/исходящие заявки и списки друзей.
- Дальше: consent-scoped location с `updated_at` и TTL, reminder/outbox с уникальным idempotency key, avatar config JSONB с версией, house и furniture placement.

Миграции только вперёд, транзакционные где поддерживаются; production применяет Flyway при согласованном деплое. Места внешнего API кэшируются только в рамках условий договора. Геолокацию хранить минимально и ограниченное время; точные координаты удалять при отключении/истечении срока, аккаунт деактивировать и очищать/анонимизировать по опубликованной политике и применимому праву. Не сохранять треки по умолчанию.
